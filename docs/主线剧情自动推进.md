# 主线剧情自动推进（新增任务）

在 MFABD2 现成框架上加的一个任务，不是外挂脚本：走 MaaFramework 的 Pipeline + 现成控制器，
所以「后台运行、不抢鼠标」用的是框架本来就有的能力。

---

## 一、改了什么

| 文件 | 改动 |
| --- | --- |
| `assets/resource/base/pipeline/Story.json` | **新增**。14 个节点，模块前缀 `Story_`，入口 `Story_Start` |
| `assets/interface.json` | 注册任务「`[执行]主线剧情自动推进`」，排在任务列表第一位 |
| `assets/interface.json` | 两个 PC 控制器的 `screencap` 由 `PrintWindow` 改为 `Background`（原因见第四节） |
| `docs/主线剧情自动推进.md` | 本文 |

没有改任何原有节点，没有加自定义识别/动作，不需要重装 Agent。
`release_interface.py` 的 `verify` 闸门拿源文件重算，两边一致（win / android / macos 三个平台都验过）。

---

## 二、怎么跑

1. 启动《棕色尘埃2》PC 客户端，**自己先走进主线卡带地图**（画面右侧能看到「◇ 主线 …」的任务追踪）。
2. 打开 MFAAvalonia，控制器选 **`PC客户端`**（描述是「鼠标不抢，窗口移动，默认后台最小化」）。
3. 任务列表勾 **`[执行]主线剧情自动推进`**（已置顶），点开始。

挂机时：

- 游戏窗口**不要最小化**，可以被别的窗口挡住——实测遮挡状态下 `FramePool` / `Background` 仍能抓到实时画面。
- 脚本点的是窗口消息，不移动你的鼠标、不抢键盘，可以同时用电脑。

---

## 三、它是怎么判断的

循环走 `Story_Start` 这张优先级表，从上往下第一个识别成功的就执行：

| 优先级 | 状态 | 识别方式 | 动作 |
| --- | --- | --- | --- |
| 1 | Agent 失联 | 复用框架 `Env_AgentLost_Stop` | 安全停下 |
| 2 | 战斗胜利 | OCR `VICTORY` | 点画面中部继续 |
| 3 | 战斗失败 | OCR `DEFEAT` / `END` | 点画面中部继续 |
| 4 | 自动战斗中 | OCR `自动战斗中`（复用 AutoBattle 的两个识别点） | 原地等，直到出结算 |
| 5 | 剧情对话 | 模板 `Chaga_ProductNext.png` / `UI_talk.png`（气泡右下角的继续箭头，全屏匹配） | 点箭头推进一句 |
| 6 | 确认弹窗 | OCR `确认` / `确定` | 点掉 |
| 7 | 卡带开头 | 右上角模板 `UI_Skip.png` / `Chaga_ProductNext.png` | 点跳过/下一步 |
| 8 | 手动战斗 | OCR `BATTLE`/`TURN`/`更换`（复用 AutoBattle） | 点顶部 AUTO |
| 9 | 在地图上 | OCR 右侧 `主线`（ROI `[995,50,285,75]`） | 点任务追踪，尝试自动寻路/开任务面板 |
| 10 | 其它 | 兜底 `DirectHit` | 点屏幕中央（走位、推进对话、关掉误开的面板） |

设计取舍：**主线里「走路」和「推进对话」是同一个动作（点地面/点气泡）**，所以第 10 条兜底
实际上承担了大部分推进工作，其余节点只负责把「卡死状态」（结算页、弹窗、战斗）处理掉。

## 四、为什么动 screencap（重要）

这台机器上实测了 MaaFramework 的 Win32 截屏方式（游戏在后台、被别的窗口盖住）：

| 方式 | 结果 |
| --- | --- |
| `PrintWindow` | **失败**，`PrintWindow failed, error code: 5`（拒绝访问） |
| `DXGI_DesktopDup` | 失败，`DuplicateOutput failed ret=-2005270524` |
| `GDI` | 能出图，但抓到的是**过期帧**（画面停在几步之前的对话），不能用于识别 |
| `ScreenDC` / `FramePool` / `Background` | **正常**，三者在同一时刻抓到的画面一致 |

`interface.json` 里原来写死 `"screencap": "PrintWindow"`，在这台机器上会导致 PC 模式黑屏/识别不到。
改成 `"screencap": "Background"`——它是「后台方案全家桶 + 自动挑一个能用的」，`PrintWindow` 能用时
仍会用它，不能用就自动降级，严格来说更稳。

另一个可试的方向：让 MFAAvalonia **以管理员身份运行**，`PrintWindow` 的 error 5 可能就消失了。

## 五、卡住了怎么调

1. 先看 MFAA 日志墙 / `debug/maafw.log`，找到最后命中的是哪个 `Story_*` 节点，就知道卡在哪种状态。
2. 用 MFAA 的截图功能截一张「卡住时」的画面发我，我按真实画面补模板或改 ROI。
3. 常见卡点：
   - **对话推进不动**：气泡的继续标记可能不是 `Chaga_ProductNext` 那个箭头形态 → 需要新增一张模板图。
   - **选择支/解谜**：脚本只会点中央，选不对就停在那儿，需要人工。
   - **奖励弹窗点不掉**：弹窗按钮不在 `[400,330,480,200]` 这个范围 → 调 `Story_Msgbox_Confirm` 的 ROI。
   - **战力不足反复失败**：`DEFEAT` 被点掉后回到地图又撞同一场战斗，会死循环，先把战力拉起来或换简单关卡。

## 六、已知边界（别踩坑）

- **不会自己进卡带**。得你先把人物放到主线卡带地图里再启动任务。
- **不走复杂寻路**。卡带有必须绕路/解谜的段落时，它只会朝屏幕中央点，可能原地打转。
- **主线战斗默认要开 AUTO**。第 8 条能点自动战斗，但用的是 PVE 战斗那套模板，主线战斗界面若不同，可能点不到。
- **OCR 依赖资源包里的模型**。从 release 包或 `install.py` 装的才有模型；只 clone 源码（`MaaCommonAssets` 是空 submodule）OCR 跑不起来。
